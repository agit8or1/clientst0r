# Competitive program — Phase 0 gap analysis

Internal planning document. Competitor product names appear here because this is a benchmark; they must not
be carried into `docs/ROADMAP.md`, FEATURES.md or marketing prose.

Companion documents in this directory: `SECURITY_REVIEW.md`, `INTEGRATION_TEST_MATRIX.md`,
`PRIORITIZED_ROADMAP.md`.

## Method

- **Code base.** Static reading of Clientst0r `main` at v3.17.719 (`1de245ac`) for the two audits, re-checked
  where noted against v3.17.720 (`58a83b32`, this worktree). Nothing was run: no test suite, no server, no
  migration. "Implemented" means a caller exists (view, signal or scheduler task), not that the path was
  exercised.
- **Rem0te.** Read-only audit of Rem0te HEAD `2dab9ef` (v0.67.0) and its `docs/contracts/ticket-rmm-v1`,
  diffed against Clientst0r's vendored copy (`integrations/rem0te/contract/`, pinned to 0.30.1 `4b2b9f5c`).
  Paths prefixed `r0:` are in the Rem0te repository.
- **Benchmark.** Official documentation of ten products: Syncro, Atera, NinjaOne, HaloPSA, ConnectWise
  (PSA/Automate), Autotask (Datto), IT Glue, Hudu, ITFlow, GLPI. One to three official pages per product;
  Atera's main site returned HTTP 403. A product not named in the Benchmark column means "not documented on
  the pages reached", not "absent". Counts are documented Yes + Partial + Add-on/Integration out of 10.
- **Verification flags.** `(unverified)` marks a claim the audit inferred from code and flagged "verify". A
  few audit claims were re-read for this document; corrections are stated in the row (for example the
  GraphQL CSRF item, which is dead code, and the vault extension item, which is bearer-only).
- **Existing roadmap.** Each row names the roadmap phase it would extend. Phases 82–90 already plan most
  monitoring, SIEM and wallboard work; this matrix does not re-plan them, it records what is still missing
  inside them.

Priority key: **P0** fix or verify before any feature work; **P1** next increments; **P2** planned within the
program; **P3** later or opportunistic.

## Executive summary

1. The Rem0te remediation chain has never run end to end: CI pairs real applications but stops at alert → ticket and analysis jobs; diagnostics, proposal → approval → result → ticket update are untested.
2. The cross-peer E2E is pinned to Rem0te 0.30.1, 37 minor versions behind Rem0te HEAD (0.67.0); runtime pairing with 0.67 has not been run.
3. Rem0te 0.55–0.67 added alert kinds (drive, uptime, updates, warranty, agent-silent) that it silently does not send, plus a `DIRECT_MODE_PORTAL_ONLY` refusal Clientst0r does not map.
4. Contract revision 3 (diagnostics, fixes, remote launch, handoff, device summary) was agreed 2026-11-11 and is unbuilt in Rem0te; revisions 4–6 proposals from Rem0te are unanswered by Clientst0r.
5. The workflow-rule engine has no re-entrancy guard on `ticket.save()` (code-read at v3.17.720, not reproduced) and a `create_charge` action with no cap or approval; there is no execution log and no dry run.
6. Billing is fed by hand-typed quantities: recurring client Charges are a stub, `ContractMeter` and `ClientServicePlan` are not consumed, and RMM endpoint counts never reach billing or reconciliation.
7. 15 of 16 listed security vendors have no adapter (Defender is a stub); security-alert auto-tickets have no dedup; the Phase 82 event layer has no consumers yet.
8. Migration importers exist only for IT Glue and Hudu; ITFlow, HaloPSA, ConnectWise, Autotask and Syncro are live ticket mirrors with no dry run, rollback or integrity report.
9. Security findings to verify first: PBS SSRF, unvalidated bulk document upload, invoice approval without separation of duties, cross-customer workflow assign/watch, audit log without tamper evidence or retention.
10. Benchmark: SLA business-hours calendars (2/10 document them), CSAT (5/10), alert dedup (1/10) and AI guardrails (1/10) are where Clientst0r's gaps are visible to buyers; dry-run automation and wallboard TV modes are not documented by any of the ten.
