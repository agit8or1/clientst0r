## Findings

- **C02**: FINDING (protocol): a suspended connection answers the token endpoint with invalid_client, the code a revoked one uses, so the other side is Security Blocked with peer_revoked. On resume, A's commit test is refused by the blocked B (its token endpoint serves only active or testing connections) and A is blocked with peer_revoked too; each side's retest is refused by the other's blocked state, so the pair cannot recover without pairing again. Fixing it needs a distinct protocol error for a suspended connection (or a protocol rule for retests), so it is reported, not changed.
- **V03**: Revoking removes the connection's source rules on B, so A's next request is refused by B's source layer before authentication and A shows source_not_authorised ("your egress may have changed") rather than peer_revoked. The block and the no-reconnect rule hold; only the reason shown to A's administrator is misleading.
