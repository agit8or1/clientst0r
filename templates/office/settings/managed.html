One editor container (ONLYOFFICE Docs or Collabora Online Development Edition, one at a time), pinned to a release and image digest from clientst0r's release list, runs on this server for this deployment only. clientst0r keeps every document and revision; the editor only holds working copies. Lifecycle actions run through the root-owned Office service helper, which accepts a fixed list of operations and nothing else. Setup of the server side (Docker prerequisites, the helper socket, which engines and address layouts are allowed) is a one-time root step: scripts/office/install-editor.sh --mode managed-local, see docs/office/MANAGED_LOCAL.md.

Address and reverse proxy

The helper writes only its own Nginx files (a dedicated site, and a snippet for the same-host layout), runs nginx -t before every reload and puts the previous files back if anything fails. It never edits clientst0r's own site.

Same host as clientst0r. Collabora's front-end (/browser, /hosting/discovery, /hosting/capabilities, /cool/) is served on clientst0r's own origin. Mitigations in place: Cookie and Authorization headers are stripped before requests reach the editor and Set-Cookie is dropped from its replies, the editor may be framed only by clientst0r, its admin console and metrics are blocked, and its access log is off (the WOPI token is in the URL). Update

Updates are manual by default. The helper downloads the pinned image before any downtime, drains sessions, takes a backup with the editor stopped, starts the new release and verifies health; clientst0r then runs an open/edit/save round trip before users can edit again. A new release that never becomes healthy is replaced by the previous one automatically. Ordinary clientst0r updates never update or restart the editor.
