One ONLYOFFICE Docs container, pinned to a release and image digest from clientst0r's release list, runs on this server for this deployment only. clientst0r keeps every document and revision; the editor only holds working copies. Lifecycle actions run through the root-owned Office service helper, which accepts a fixed list of operations and nothing else. Setup of the server side (Docker prerequisites, the helper socket, the office host name in Nginx) is a one-time root step: scripts/office/install-editor.sh --mode managed-local, see docs/office/MANAGED_LOCAL.md.

Update

Updates are manual by default. The helper downloads the pinned image before any downtime, drains sessions, takes a backup with the editor stopped, starts the new release and verifies health; clientst0r then runs an open/edit/save round trip before users can edit again. A new release that never becomes healthy is replaced by the previous one automatically. Ordinary clientst0r updates never update or restart the editor.

Uninstall

Drains sessions, then removes the container. Documents and revisions in clientst0r, the editor's working data, its secrets and backups are kept. Deleting the editor data is a separate step from a root shell on the server: sudo clientst0r-office-helper cli purge --confirm {{ status.config.deployment_id|default:"<DEPLOYMENT_ID>" }}.
